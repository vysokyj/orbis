# Calibration — checking the export against Iray

ORBIS translates what a DAZ scene *means* into Octane. Whether a rule is
right is decided by rendering the same scene in both and measuring — every
rule in the [spec](spec/octane-export.md) carries the numbers it was fitted
on. This page is the how.

## The principle

**The scene as Iray lights it, rendered the way Octane renders.** Match what
the scene asks for — light amounts, exposure, colours, which surfaces
reflect, transmit or glow, the sun / sky balance. Where Octane does
something more plausibly than Iray (a low sun's warm colour, a gloss layered
over the diffuse, a spot's soft edge) keep Octane's. The export's
[Look](spec/octane-export.md#look)
switch lets the user lean either way.

Rules come from **calibration scenes**, never from one production scene: a
fix has to hold on scenes built to test exactly that.

**What DAZ hands Iray is read, not fitted.** DAZ's own `.mi` export of the
calibration scenes says exactly which MDL parameters it computes from the
channels (`scripts/dev/daz-export-mi.dsa` → `scripts/dev/mi-oracle.py` →
`calib/references/mi/*.json`). Those conversions live in `src/iray.rs`,
tested against every fixture; they outrank any calibration result.
Calibration tunes only the Octane side — how Octane renders those
parameters. A render that seems to contradict `src/iray.rs` points at the
Octane side, never at the verified conversion (#62).

**A real material renders off? Its `.mi` first.** Before an Iray batch or
a theory from the MDL, export the scene's `.mi` and compare what DAZ hands
Iray with `src/iray.rs` (`mi-args.py`) — for a store product too (kept
local, never in git; prove the rule on a generated scene). DAZ computes
things the MDL never sees, and from more than the channel values: the
SSS Reflectance Tint enters the diffuse only while Base Color Effect is
saved *shown* (`"visible"` in the DSON), which DAZ's default material —
the base of our generated scenes — saves hidden. So a rule that holds on
the calibration spheres can still miss product content: when a product
and a sphere with the same values disagree, copy the product's whole
channel list onto a sphere and bisect it (#52 took three Iray batches
before the `.mi` showed the tint in one look).

**Every channel rule is tested hidden and shown.** A `.mi` sweep of
generated spheres proves only DAZ's hidden-channel behaviour; each sweep
gets a `-Shown` twin (the same scene with every `visible` key dropped), and
a difference between the twins is a gate to pin down and record (the
`mi-fixture` skill has the procedure; the gates found so far:
`docs/daz/iray-uber-mdl.md`, Channel visibility).

**Four variants, one at a time.** An export is one of Look (Enhanced /
Faithful) × render mode (Final / Preview). Calibrate **Enhanced + Final**
(path tracing, the photoreal one) first, then run the same scenes for each
of the other three and tune them on their own. Whatever differs between
variants is a named, per-variant value in the code and a column in the
spec, so every exception can be traced back.

## The loop

1. **Scene** — `scripts/dev/make-calib-scenes.py` and
   `scripts/dev/make-light-scenes.py` write the scenes into DAZ's
   "My Library/Scenes" (kept if present; `--force` rewrites). Scenes that
   need DAZ itself (new geometry, a shader preset) are built headless:
   `daz-build-leaf-scene.dsa`, `daz-build-sundir-scene.dsa`,
   `daz-apply-presets.dsa` via `scripts/dev/daz-script.sh`. Copy a new
   generated scene into `calib/scenes`.
2. **Iray reference** — `scripts/dev/calib-render.py [--auto-ev]
   [--samples N] <scene.duf>…`: a headless DAZ Studio render, capped by
   samples so every variant has the same noise; `--auto-ev` sets the
   scene's exposure first. The renders go through one DAZ Studio instance
   (`orbis-render`) that stays open between them: `daz-render.sh` starts
   it on the first render with `daz-render-queue.dsa` and hands it each
   scene through `~/Library/Caches/orbis/calib/queue-local`, under the
   render lock; `daz-render.sh --stop` quits it. Output:
   `~/Library/Caches/orbis/calib/iray`;
   copy the generated scenes' renders into `calib/references/iray`.
   Render a variant at its reference's samples (the default is 400; Calib-
   Eye's reference is 100) — time grows with them: Calib-Thin 22 s at 100,
   Calib-Eye 228 s at 100 without its strand hair, 318 s with it, 1280 s
   at 400. Test a material on primitives first (Calib-Thin, -SSS), a
   figure only to confirm.
   **On an Iray Server** (Boost for Daz, GPUs by the hour): its Bridge
   connection lives only in the DAZ Studio that made it, and a second
   DAZ Studio launch with a script starts its own instance rather than
   handing the script over. So: start the session, open DAZ Studio, Render
   Settings > Advanced > Bridge — server, username, password from the
   session, Secure off, Connect, Rendering Enabled — then Render > ORBIS
   Iray Queue (`scripts/dev/daz-render-queue.dsa`; it replaces the open
   scene). The menu item is added once by `daz-add-queue-menu.dsa` (run
   in a DAZ Studio instance with the queue script's path as argument).
   `scripts/dev/iray-queue.sh [-s samples] [-o out dir] <scene.duf>…`
   queues capped copies (Max Time 0, as Boost asks) and collects the
   renders into the Iray references; `iray-queue.sh --stop` ends the queue.
   Worth it for small scenes; a figure's textures take long to upload.
3. **Dump and export** — `scripts/dev/daz-dump.sh <out dir> <scene.duf>…`
   writes the scene dump (the posed geometry) and the `.orbx`.
4. **Octane render** — `scripts/dev/octane-render.sh <out dir> [samples]
   <scene.orbx>…` renders each export as exported, unattended (Octane X is
   driven through its Script menu).
5. **Compare** — `scripts/dev/calib-compare-all.py <octane dir>`: Octane /
   Iray in linear luminance per sphere, light region or frame, plus side-by-
   side images. 1.00 = equal.
   **Per variant** — `scripts/dev/calib-variants.sh [-s samples]
   <variant>… -- <scene>…` (`enhanced-final`, `faithful-final`,
   `enhanced-preview`, `faithful-preview` or `all`) re-exports the scenes
   from their cached dumps in that variant, renders and compares them into
   `octane/<variant>/report.md`.
6. **Hypotheses** — `scripts/dev/orbx-variants.py <in.orbx> <dir>
   <hypothesis>…` rewrites pins of an export (IOR, specular, coating,
   turbidity, …) to test a rule before coding it; render and compare the
   variants like any export.
7. **Record** — the rule and its numbers go into the
   [spec](spec/octane-export.md) in the same commit as the code; Octane facts
   into [octane/octane-x.md](octane/octane-x.md). The whole session — tries,
   dead ends, numbers, timings — goes into a dated note in
   [notes/](notes/README.md).

## Rules for the machines

- **`make-calib-scenes.py --force` rewrites every generated scene** in My
  Library (exposure tuned by hand included). To rebuild one, delete that
  `.duf` and run the script without `--force`; restore from `calib/scenes`
  if it happened.

- **Never a DAZ render and an Octane render at once** — Iray takes the
  whole CPU; the scripts refuse.
- **Octane X needs an unlocked screen**: behind a lock it never leaves its
  simple mode and has no Script menu. Keep the Mac awake (`caffeinate`).
- Octane X now and then crashes on its own at start-up: `octane-run.sh`
  launches it again (twice at most) when it is gone before the probe is
  done.
- Octane X is sandboxed: probes and renders read and write its container's
  Documents; `octane-run.sh` links the scene there.
- A DAZ render can take hours at full quality — cap it (`daz-render.sh
  <scene> <out.png> [seconds] [samples]`).
