# 2026-11-04 — Diffuse Overlay with maps (#71)

Goal: export Iray Uber's Diffuse Overlay when its Weight or Color is
mapped (left out until now; the channel audit finds an overlay weight map
in 83 of 420 scenes — shoe soles, alpha masks). Variant: enhanced-final.

## What DAZ and Iray do

- `irayubermaterial.mdl`: `diffuse_bsdf` is a `weighted_layer` of a
  second `diffuse_reflection_bsdf` (overlay colour, overlay roughness) at
  `diffuse_overlay_weight` over the base diffuse / translucency mix —
  the overlay replaces that share. Weight and colour are plain `float` /
  `color` arguments, so DAZ may feed them textures.
- New scene **Calib-Overlay** (`make-calib-scenes.py`): eight flat red
  Uber spheres (as Calib-Diffuse), no gloss. Maps are ours, generated by
  the script: `calib-overlay-weight` (latitude belts at 1, 0.5, 0.25, 0,
  twice; 8-bit grey, `map_gamma` 0) and `calib-overlay-colour` (8 × 8
  blue / yellow checker).

  | sphere | overlay |
  |---|---|
  | V1 | weight map, w 1, white |
  | V2 | weight map, w 1, Weight Squared |
  | V3 | weight map, w 0.5, Weight Squared |
  | V4 | colour map, w 0.5 |
  | V5 | colour map, w 0.5, Weight Squared |
  | V6 | both maps, w 1 |
  | V7 | both maps, w 0.6, colour 0.5 / 0.8 / 1 |
  | V8 | both maps, w 1, Overlay Roughness 1 |

- DAZ's `.mi` export (fixture `calib/references/mi/Calib-Overlay.json`):
  - the weight map is `texture_return.mono(file_texture(…, color_scale
    w))`, gamma auto; with Weight Squared wrapped in
    `irayubermaterial::square_float` — **the map × w squared as a whole**
    (V3: `color_scale` 0.5 inside `square_float`, so 0.25 m²). The old
    rule squared the value only and passed a float where DAZ passes the
    texture call; `src/iray.rs` now passes the map (`Map.squared`), as it
    does for roughness maps.
  - the colour map is `texture_return.tint(file_texture(…, color_scale =
    the linear colour))` (V7: 0.2176 / 0.612 / 1 = 0.5 / 0.8 / 1 ^ 2.2),
    as every colour channel; this was already right.
  - a flat weight with a colour map squares the value (V5: 0.25).

## Octane

- Albedo = Mix texture (38): amount = the weight (a float, or the weight
  map as a greyscale image at its data gamma — 2.2 for an 8-bit map
  without its own, #49 — doubled when squared, `power` w or w²), texture1
  = the base (its colour, or its map as before), texture2 = the overlay
  colour × the specular share × the overlay's Oren-Nayar flat term (#32),
  × its colour map when there is one. Squaring by twice the gamma is exact
  for a map read through a power curve: (w · m^g)² = w² · m^(2g).
- Flat over flat stays one folded colour (no change for Calib-Diffuse /
  Calib-Map-Effect). New as a side effect: a **flat overlay over a diffuse
  map** was dropped before (only the no-map branch mixed it); it now gets
  the Mix too. OOT hair's Overlay Alpha Mask blend keeps its own path.
- Color Effect on a mapped colour acts on the tint only (the map's own
  colour isn't known at export).

## Render (sanity only)

Octane, enhanced-final, 400 samples: V1 shows white belts fading to the
red base (0.5 / 0.25 belts at 2.2: 0.22 / 0.05 overlay), V2 / V3 the
same belts darker (squared), V4 / V5 the checker half over red (V5 at a
quarter), V6 – V8 the checker on the weight belts only, V7 tinted, V8
duller (Oren-Nayar flat term). Compared with Iray on 2026-11-05
([note](2026-11-05-overlay-maps-iray.md)): the squared belts had not
reached Octane (sRGB ignores the gamma pin), fixed there.

## Lessons

- The `.mi` fixture settled the squaring question in one DAZ run; the
  fixture test failed on the old rule for all six weight-map spheres
  (`DAZ None, ours Float`), which is the proof `src/iray.rs` needed.
